## Phase 1: 결핍 인식 (Aporia)

7개 기획 문서를 4가지 결핍 유형으로 스캔.

### 발견된 핵심 결핍 3개

| 유형 | 결핍 | 사용자 답 |
|---|---|---|
| **검증의 결핍** | "수동 보고서 30~60분 → AI X초"라는 가치 명제의 수치 근거 부재 | 행정·안전 업무 경험 기반 **합리적 추정** (실측 X) |
| **무지의 결핍** | 현장 안전 담당자가 본 시스템을 거부할 가장 큰 이유 | **AI 결과 신뢰 부족** (검토가 오히려 일이 됨) |
| **이해의 결핍** | F2 특보 매칭의 "영향권 학교" 정의 | **모르겠음 — 전문가 자문 필요** |

### 결핍의 의미

- **검증 결핍**: 기획서에 "추정" 명시 또는 자체 측정 추가 필요
- **무지 결핍**: 검토 비용 ≥ 수동 작성 비용이면 시스템 가치 부정 — **최대 위협**
- **이해 결핍**: "100% 매칭 정확도"는 코드 결정론적 일관성일 뿐, 현실 영향 정확도는 영향권 정의에 종속

## Phase 2-3: 욕망 발동 + 다이몬 중재

### 욕망 (결핍 → 목표 상태)

| 결핍 | 욕망 | 목표 상태 |
|---|---|---|
| 수치 미검증 | "측정 가능한 가설로 변환" | PRD에 "추정/가설" 표시 + 자체 측정 |
| AI 신뢰 부족 | "출처·근거·편집을 노출" | 보고서에 매뉴얼 인용 + 편집/diff + 정확도 피드백 |
| 영향권 정의 모호 | "잠정 정의 + 확장 구조" | "현재는 region 일치, 향후 거리/지형 가능" 명시 |

### 다이몬 (Atlas 내부 점검)

- ✅ 이미 있음: `draft.source` (cli/sdk/template) — AI 출처 표시
- ❌ 빠짐: 보고서 본문에 매뉴얼 조항 인용 마킹
- ❌ 빠짐: 매칭 로직 확장 인터페이스 (현재 `match_schools()` region 비교 하드코딩)
- ❌ 빠짐: 사용자 정확도 피드백 채널

## Phase 4: 디오티마 사다리 (Layer 0 → 5)

| Layer | 추상화 | 사용자 결정 |
|---|---|---|
| **L0** 개별 사례 | 검증 안 된 가치 명제 1, 정의 모호 1, 거부 요인 1 | — |
| **L1** 같은 형태 사례 | 공공 행정 AI 도입 일반: 챗봇·민원분류·문서자동화 | — |
| **L2** 공통점 | 도입 결정자는 **측정·투명·확장** 3축으로 검토 | **+ KPI 트랜스퍼런스 4축 확장 동의** |
| **L3** 원리 | "AI 보조판단은 정확성보다 **검증 가능성**으로 판단됨" | **3가지 적용 모두 동의** (근거 인용 + 편집/diff + 정확도 피드백) |
| **L4** 관계 | 측정·신뢰·확장: 서로 강화하는 positive feedback loop | **3 동시, 출품 기한 고려 시간 배분** |
| **L5** 보편 원리 | "기획은 결핍을 측정·검증가능한 가설로 변환하는 작업" | **01-prd.md 압도적 수치·정의 전부에 '잠정/가설' 표시** |

### 보편 원리 도달

> **기획은 결핍을 측정 가능한 가설로 변환하고, 가설을 검증 가능한 코드로 변환하는 작업이다.**
> AI 보조 시스템 = 측정·검증·확장의 3축에서 거리를 좁히는 프로젝트.

## Phase 5: 창작 (Poiesis) — PRD v1.0 → v1.1 패치

### 변경 사항

1. **§0 가설/검증 표기 규약** 신설 — 5가지 마커 ((가설)/(추정)/(잠정 정의)/(측정중)/(측정 완료)) 정의
2. **핵심 가설 트래커** 표 신설 — 6개 핵심 항목의 현 상태 + 검증 계획
3. **검증 가능성 강화 약속** 신설 — 근거 인용 + 편집/diff + 정확도 피드백 3가지 명시
4. **§8 KPI 표에 "검증 상태" 컬럼** 추가 — 5개 기존 KPI + K6 (KPI 트랜스퍼런스) 신설

### 패치 결과

- 01-prd.md: 511줄 → 약 555줄 (+44줄)
- 영향: 모든 후속 문서(02~07)는 PRD를 참조하므로, 자동으로 v1.1 정신 반영됨
- 차후 작업 (M5~M11)은 가설 트래커의 "검증 계획" 컬럼을 따라 진행
