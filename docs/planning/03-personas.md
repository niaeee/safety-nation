safety-nation의 3대 사용자 정의 및 사용 시나리오

## P1: 시도/지원청 안전 담당 공무원

### 기본 정보

| 항목 | 내용 |
|---|---|
| **역할** | 광역 수준(시도/지원청)의 재난 대응 및 안전 정책 실행 |
| **직책** | 과장, 팀장, 전담 공무원 |
| **연령대** | 30~55세 |
| **PC 숙련도** | 중상 (엑셀, 공공 시스템 이용 경험 있음) |
| **근무 환경** | 옥상 사무실, 사무용 컴퓨터 + 모바일 |

### 일과 흐름

**평시 (비상황)**
1. 09:00 ~ 12:00: 메일·공지 확인, 학교 안전 컨설팅
2. 12:00 ~ 14:00: 점심 시간
3. 14:00 ~ 17:00: 보고서 작성, 정책 기획, 회의

**특보 발령 시 (즉각 대응)**
1. 09:30 (호우주의보 발령) → 휴대폰으로 긴급 뉴스 알림 수신
2. 09:35 → 사무실 복귀, safety-nation 시스템 접속
3. 09:40 → "호우주의보" 클릭 → 영향학교 자동 식별 (초동 30초)
4. 09:45 → AI 보고서 초안 수신 (10초)
5. 09:50 → 초안 검토 (5분)
6. 10:00 → 담당 국장에게 보고서 제출 (완료)
7. 10:30 ~ 12:00 → 필요 시 추가 의사결정 (휴교 연장 등)

### 본 시스템 사용 시점

- **정시성**: 특보 발령 후 15~30분 내에 보고서 완성
- **빈도**: 호우/강풍/대설 특보 발령 시 (연 5~10회)
- **압박도**: 높음 (상급자 보고 deadline 있음)

### 핵심 가치

| # | 가치 | 영향 |
|---|---|---|
| **V1** | 영향학교 수십 개를 손으로 찾지 않아도 됨 | 초동 시간 2시간 → 30분으로 단축 |
| **V2** | 보고서 초안을 AI가 자동 작성 | 작성 시간 1~2시간 → 10분으로 단축 |
| **V3** | 광역 데이터를 지도로 한눈에 조회 | 의사결정 근거 명확화 |
| **V4** | 이전 유사 특보 사례를 자동 추천 | 의사결정 경험 축적 |

### 사용 시나리오: 호우주의보 발령 시 30분 내 보고 완료

**배경**: 
- 오전 9시 호우주의보 발령 (서울특별시)
- P1 담당자 현재 타지역 출장 중 (40분 귀사 소요)
- 상급자로부터 30분 내 보고서 요청

**시나리오**:

```
시점       |  P1 행동                          | 시스템 상태
-----------|-----------------------------------|--------------------------
09:30      | 휴대폰 긴급뉴스 수신              | 호우주의보 발령
09:32      | 사무실 복귀 지시                  | -
09:35      | "safety-nation 앱" 접속           | 데모 모드 ON
09:36      | "활성 특보" 섹션에 호우주의보 표시| 특보 카드 클릭
09:37      | "매칭" 버튼 클릭                 | 서울 영향학교 검색 (2초)
09:38      | 지도에서 붉은 학교 마커 확인      | 마커 강조 + 테이블 표시
           | "영향학교 121개" 확인             |
09:39      | AI 보고서 초안 읽음 (10초)       | 초안 자동 생성 완료
09:44      | 초안 검토 및 2~3군데 수정         | 텍스트 편집
09:47      | "저장 및 제출" 버튼 클릭         | DB 저장 + 로그 기록
09:48      | 보고서 링크를 메일로 공유         | 완료
09:50      | 상급자 보고 ("30분 내 완료")      | -
```

**성공 조건**:
- ✅ 15분 내 영향학교 식별
- ✅ 초안 생성 시간 ≤ 10초
- ✅ 최종 보고 시간 30분
- ✅ 담당자 검토 시간 ≥ 5분 (품질 보증)

## P2: 단위학교 안전 담당교사

### 기본 정보

| 항목 | 내용 |
|---|---|
| **역할** | 학교 내 안전 담당, 학교장 보좌 |
| **직책** | 교사 (겸무), 주로 보직 담당자 |
| **연령대** | 30~50세 |
| **PC 숙련도** | 중 (업무용 PC 이용 중) |
| **근무 환경** | 학교 행정실 사무실 또는 자신의 교실 |

### 일과 흐름

**평시**
1. 08:00 ~ 09:00: 등교 지도 및 조회
2. 09:00 ~ 15:30: 수업 진행 (틈틈이 행정실 방문)
3. 15:30 ~ 16:30: 학생 하교 지도 및 행정 업무
4. 16:30 이후: 퇴근 또는 추가 업무

**특보 발령 시 (긴급 대응)**
1. 14:00 (대설주의보 발령) → 행정실 직원으로부터 알림 수신
2. 14:05 → 수업 잠깐 중단, 행정실 방문
3. 14:08 → 휴대폰으로 safety-nation 접속
4. 14:10 → 자신의 학교 검색 → "영향권 O" 확인
5. 14:12 → 학교장에게 긴급 보고 ("대설, 우리 학교 영향권")
6. 14:30 ~ 15:00 → 학교장 지시에 따라 조치 (휴교/원격 수업 등)
7. 15:30 → 학부모·학생에게 공지

### 본 시스템 사용 시점

- **정시성**: 특보 발령 후 10~15분 내
- **빈도**: 특보 발령 시 1회 (자신의 학교만 확인)
- **압박도**: 중상 (학교장 지시 대기, 학생 안전 책임)

### 핵심 가치

| # | 가치 | 영향 |
|---|---|---|
| **V1** | 본인 학교가 영향권에 있는지 즉시 확인 | 보고 시간 수십 분 → 5분 |
| **V2** | 객관적인 근거로 학교장에게 보고 | 의사결정 신뢰도 향상 |
| **V3** | 다른 학교의 대응 사례 참조 | 의사결정 경험 공유 |
| **V4** | 학부모 설명에 근거 제시 | 신뢰 관리 |

### 사용 시나리오: 대설주의보 발령 시 학교장 보고

**배경**:
- 오후 2시 대설주의보 발령 (전국)
- P2 교사 현재 3학년 2반 수업 진행 중
- 학교장이 정확한 정보를 요청

**시나리오**:

```
시점      |  P2 행동                          | 시스템 상태
---------|-----------------------------------|--------------------------
14:00    | 교무실로부터 특보 알림             | 대설주의보 발령
14:05    | 수업 종료 후 행정실 방문          | -
14:08    | 휴대폰으로 safety-nation 앱 실행  | 데모 모드 ON
14:09    | "학교 검색" → "우리 학교 입력"     | 검색창에 "○○중학교"
14:10    | "검색" 클릭                       | 학교 마커 강조 + 영향도 표시
         | "영향권: O (중학교, 위험도 0.8)"  |
14:11    | 학교장실로 이동                    | -
14:12    | 학교장에게 보고                    | 앱 화면 공유
         | ("대설주의보, 우리 학교 영향권")  |
14:13    | 학교장 지시 대기                   | -
14:30    | 학교장으로부터 원격수업 지시       | -
14:35    | 행정실에서 학부모 안내 문자 발송   | -
14:40    | 학부모 안내 사항 공지              | -
```

**성공 조건**:
- ✅ 5분 내 본인 학교 영향 확인
- ✅ 학교장에게 객관적 근거 제시
- ✅ 대응 시간 ≤ 30분 (조치 실행)

## P3: 교육행정 정책 수립자

### 기본 정보

| 항목 | 내용 |
|---|---|
| **역할** | 교육청/도교육청 정책 기획, 통계 분석 |
| **직책** | 교육정책 담당관, 연구원 |
| **연령대** | 35~60세 |
| **PC 숙련도** | 상 (데이터 분석 경험 있음) |
| **근무 환경** | 교육청 정책 기획실 사무실 |

### 일과 흐름

**주간 업무**:
1. 월 09:00 ~ 12:00: 주간 계획 회의
2. 월~목: 정책 연구, 데이터 분석
3. 목 14:00 ~ 15:00: 보고 자료 정리
4. 금 09:00 ~ 10:00: 의사결정권자 보고

**분기 업무** (마지막 주):
1. 분기말 월~목: 반기/분기 통계 수집
2. 분기말 금: 보고서 작성 및 제출
3. 분기 후반: 정책 제안

### 본 시스템 사용 시점

- **정시성**: 분기/반기 단위 (주 1회, 30분)
- **빈도**: 분기마다 3~4회
- **압박도**: 낮음 (deadline 유연, 장기적 근거 수집)

### 핵심 가치

| # | 가치 | 영향 |
|---|---|---|
| **V1** | 특보 처리 현황 통계 (시도별·기간별) | 정책 근거 제시 시간 단축 |
| **V2** | AI 활용도 및 효과 데이터 | 예산 증액 근거 제시 |
| **V3** | 지역별 특보 빈도 트렌드 분석 | 지역 맞춤형 정책 수립 |
| **V4** | 처리시간 분포 (P50/P95) 성과 지표 | 성과평가 근거 |

- **네트워크**: 공공기관 LAN + 4G 모바일
- **지원**: 전화 및 이메일 헬프데스크 (평일 09:00~18:00)

- **지원**: 카톡/전화 문의 (빠른 응답 필수)
- **교육**: 카톡봇 Q&A, 이메일 팁

### P3 (정책 수립자)
- **디바이스**: 사무용 PC (1920x1080), 노트북
- **네트워크**: 교육청 LAN + VPN
- **지원**: 이메일 기술지원, API 문서
- **교육**: 분석 가이드 문서

## 부록 A: v1.2 신규 페르소나 (사용자 비전 재정의 결과)

### P4: 학부모

| 항목 | 내용 |
|---|---|
| **역할** | 자녀가 다니는 학교의 재난 영향 실시간 확인 |
| **사용 시점** | 특보 발령 인지 직후 (현재는 일반 재난문자, v2에서 push) |
| **빈도** | 비발령 0건, 발령 시 1~2회 확인 |
| **핵심 질문** | "오늘 우리 아이 학교 가도 되나?" |
| **사용 동선** | 메인 §1 상단 학부모 검색 박스 → 학교명 입력 → 위험 아이콘 즉시 표시 |
| **가치** | 안심 또는 능동 대응 (일찍 등교, 우산, 학부모 회의) |
| **기술 환경** | 모바일 60%, PC 40% — 반응형 필수 |

> **검증 상태**: 행동 패턴은 인터뷰 없는 **(추정)**. 출품 후 사용자 피드백으로 검증.

| 항목 | 내용 |
