## Phase 1: 결핍 재인식 (Cycle 2)

| 결핍 | 사용자 답 | 의미 |
|---|---|---|
| **검증** 시간 추정 | "**일주일 풀** 개발" | D-21 분산 → **D-7 풀타임** 압축 필요 |
| **🆕 무지** 자동 알림 | 사용자 직접 발견 — "사이트 접속해야 알 수 있는 건 약함" | **Push 인프라 부재** = 시스템 최대 약점 (사용자 인정) |
| **검증** 학부모 행동 | "당연히 궁금" — 추정, 인터뷰 X | PRD에 (추정) 마커 유지 |
| **검증** 위험도 신호 | 외부 데이터 탐색 후 노후도 fallback | W1 첫날 data.go.kr·교육데이터 탐색 1일 투자 |

### 가장 큰 새 결핍

**자동 알림(push) 부재** — 사용자가 직접 발견. "재난 정보가 오긴 한다"는 표현으로 일반 재난문자와의 차별화 부족 인정.

## Phase 2-3: 욕망 + 다이몬

새 결핍 4개를 한 줄로 묶으면:
> **"현재 시스템은 pull(수동) 위주, push(능동) 부재"**

- 알림 부재 → 시스템이 능동 통지 (push)
- 학부모 인터뷰 부재 → 시스템이 능동 의견 수집 (피드백)
- 외부 데이터 미탐색 → 시스템이 능동 fetch
- 시간 자동화 부재 → 도구가 능동 분담

**Atlas (현재 코드 점검)**: 알림 0, 외부 데이터 fetch 0, push 인프라 0. 모든 것이 사용자가 들어와야 시작되는 구조.

## Phase 4: 디오티마 사다리 (Cycle 2)

| Layer | 추상화 | 사용자 결정 |
|---|---|---|
| **L0** | 알림·인터뷰·외부데이터·시간 자동화 모두 부재 | — |
| **L1** | 공공 안전 시스템 일반: 코로나·산불·미세먼지 모두 push 부재 비판 받음 | — |
| **L2** | 현재 시스템은 pull 위주, push 부재 | **공감 — 시스템 최대 약점** |
| **L3** | 안전·재난 시스템의 가치는 능동성에 비례 | **v1에 UI 명시 알림 카드 (배너)** 도입 결정 |
| **L4** | 능동성 = 알림 + 데이터 능동 + 사용자 검증 능동 | **W1 첫날 외부 데이터 탐색 1일 투자**. 찾으면 위험도 강화, 없으면 노후도 fallback |
| **L5** | "사고 후 보고서보다 사고 전 능동 push가 시스템 가치를 결정한다" | **PRD/기획서 원라이너에 'AI 사전 예측 시스템' 명시** |

### 보편 원리 (Cycle 2)

> **안전 시스템의 진짜 가치는 사고 후 보고서가 아니라 사고 전 능동적 푸시에 있다.**
> Cycle 1의 "측정·검증·확장"이 *내부 품질* 축이라면, Cycle 2의 "능동성"은 *외부 영향* 축. 두 축이 서로를 강화한다.

## Phase 5: 창작 (Poiesis)

### 변경 사항 — 로드맵 v1.0 → v2.0

1. **시간 일정 압축**
   - D-21 분산 (W1·W2·W3 각 5~6일) → **D-7 풀타임 (5/11~5/17)** + W2~W3는 마무리·기획서·시연

2. **F7 UI 알림 카드 신설** (Cycle 2 신규)
   - 상단 배너: "⚠ 특보 N건 활성 (호우 강원, 대설 경기 …)"
   - 접속 즉시 표시 — push 인프라가 없어도 능동성 메시지 충족

3. **외부 위험 데이터 탐색 (D1 첫날)**
   - data.go.kr / 교육데이터에서 학교별 위험 자료 검색
   - 발견 시 위험도 산정 풀 강화, 미발견 시 노후도(설립일자) fallback

4. **메시지 재정렬**
   - 원라이너에 "**AI 사전 예측**" 강조 (사고 후 보고서 X)
   - "예측·자동보고"라는 기존 표현은 유지하되, 시연·기획서에서 "사전" 비중 ↑

### 변경 안 한 것 (의도적)

- **풀 push 인프라 (SMS·이메일·카카오톡)**: 시간 부족 → v2 보류
- **학부모 인터뷰**: 출품 전 시간 X → "(추정)" 마커 유지
- **권한 분리·인증**: Out of Scope 그대로
